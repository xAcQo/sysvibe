## Phase 1: CLI Foundation

**Goal:** Build the core CLI framework so `npx sysvibe` works, `sysvibe init` walks users through language selection, and `.sysvibe.toml` stores project config.

**Requirements:** CLI-01, CLI-02, CLI-03, CLI-06, GATE-07

**Success Criteria:**
1. Running `npx sysvibe` displays help with available commands
2. Running `sysvibe init` presents interactive language pack selection (C++, Rust)
3. After init, `.sysvibe.toml` exists with selected packs listed
4. Running `sysvibe add rust` adds Rust pack to existing config
5. Running `sysvibe init` with missing toolchain (e.g., no cargo) shows clear warning with install instructions

**Depends on:** Nothing (first phase)

---

## Phase 2: Language Packs + Agent Integration

**Goal:** Build C++ and Rust language packs with idiomatic rules, anti-patterns, and few-shot examples. Auto-detect AI agent and inject pack rules into correct config format.

**Requirements:** AGENT-01, AGENT-02, AGENT-03, AGENT-04, CPP-01, CPP-02, CPP-06, CPP-07, RUST-01, RUST-02, RUST-06, RUST-07

**Success Criteria:**
1. After `sysvibe init` in a Claude Code project, CLAUDE.md contains C++/Rust rules with section markers
2. After `sysvibe init` in a Cursor project, .cursorrules contains equivalent rules
3. C++ pack rules explicitly forbid raw new/delete, enforce smart pointers, require RAII
4. Rust pack rules enforce proper error handling with `?`, flag excessive `.unwrap()` and `.clone()`
5. `sysvibe init --template cpp` scaffolds a CMake project; `--template rust` scaffolds a Cargo project

**Depends on:** Phase 1

---

## Phase 3: Quality Gate Pipeline

**Goal:** Build `sysvibe check` to run quality gates (compile, lint, sanitize, test) and produce clear pass/fail reports.

**Requirements:** CLI-04, CPP-03, CPP-04, CPP-05, RUST-03, RUST-04, RUST-05, GATE-01, GATE-02, GATE-03

**Success Criteria:**
1. `sysvibe check` in a C++ project runs: g++ -Wall -Werror → clang-tidy → AddressSanitizer build+run
2. `sysvibe check` in a Rust project runs: cargo clippy -D warnings → cargo fmt --check → cargo test
3. Each gate shows ✓ PASS or ✗ FAIL with human-readable error summary
4. Pipeline exits with code 0 (all pass) or 1 (any fail)
5. `sysvibe check` with no active packs shows helpful error message

**Depends on:** Phase 1, Phase 2

---

## Phase 4: Auto-Fix Loop

**Goal:** When gates fail, automatically format errors for the AI agent, trigger a fix, and re-run until clean.

**Requirements:** CLI-05, GATE-04, GATE-05, GATE-06

**Success Criteria:**
1. `sysvibe fix` runs gates, captures failures, and outputs AI-formatted error context
2. If same error hash appears twice in a row, loop aborts with "unable to auto-fix" message
3. Max retry count defaults to 3, configurable in `.sysvibe.toml`
4. After successful fix loop, final `sysvibe check` shows all gates passing

**Depends on:** Phase 3

---

## Milestone Boundary

After Phase 4, SysVibe v1.0 is complete and ready for:
- npm publish
- GitHub repository with README, examples, and documentation
- Community feedback and v2 planning (Go pack, combo packs, CI templates)
