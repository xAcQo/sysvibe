# Requirements: SysVibe v3.0

**Defined:** 2026-05-07
**Core Value:** AI-generated systems language code must meet production-grade quality standards

## v3 Requirements

### CI/CD Integration

- [x] **CICD-01**: Provide GitHub Actions workflow template for SysVibe checks
- [x] **CICD-02**: Provide GitLab CI pipeline template for SysVibe checks
- [x] **CICD-03**: Add `sysvibe init --ci` command to scaffold CI configuration automatically

### Pipeline Optimization

- [x] **OPT-01**: Implement file-level hashing mechanism to track unchanged source files
- [x] **OPT-02**: Skip execution of heavy quality gates (compilation, linters) for unchanged files
- [x] **OPT-03**: Allow forcing full re-checks via a `--force` flag on `sysvibe check`

### Additional Language Packs

- [x] **LANG-01**: C# (.NET) Language Pack (dotnet format, build, test)
- [x] **LANG-02**: Swift Language Pack (swiftlint, swift test)
- [x] **LANG-03**: Java Language Pack (maven/gradle, checkstyle, spotbugs)

## Future Requirements (v4.0+)

- [ ] Support for Bazel build system

## Out of Scope

| Feature | Reason |
|---------|--------|
| IDE/editor plugins | SysVibe works through agent config files, not IDE extensions |
| Build system replacement | SysVibe invokes existing tools (CMake, Cargo, Zig), not replaces them |
| Web framework support | Other tools cover web; SysVibe is systems-only |
| GUI Agent Child Process Loop | GUI agents (Cursor) require developer-driven loops (`@.sysvibe/fix-prompt.md`) |
